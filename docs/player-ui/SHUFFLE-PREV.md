# 随机播放的「上一曲」= 回家，不是再掷一次骰子

日期 2026-10-09 ｜ 状态：**已改完，未部署**（请随你这一轮一起上）
改动文件：`ui/app.js`（只有这一个；没动 `verify-ui.mjs`，避免和你撞车）

## 症状

随机模式下点「上一曲」，也随机到另一首，和意图不符。
「下一曲随机」是对的，保留不动。

## 做法

随机模式里维护一条「听过的路」（uid 栈，**末尾永远是当前曲目**）：

- **换曲**（下一曲 / 自动续播 / 点队列跳曲）→ 压栈
- **上一曲** → 先弹掉当前，再取新的末尾（＝真正听过的那一首）
- **路走空**（刚开始听、或换了歌单）→ 退回**顺序上一首**，不再随机

栈随 playback-state 快照落盘（字段 `shuffleTrail`），拖进/拖出换文档也还在。

## 四个触点（全在 `ui/app.js`）

| # | 位置 | 改了什么 |
|---|---|---|
| 1 | `stepIndex()` 上方 | 新增 `SHUFFLE_TRAIL_MAX` / `shuffleTrail` / `shuffleTrailPush()` / `shuffleBackUid()` |
| 2 | `stepIndex()` | shuffle 且 `dir < 0` 时走来路；`dir > 0` 仍随机；其它模式分支原样不动 |
| 3 | `playTrack()` | `state.currentUid = uid` 之后，`changed && mode === 'shuffle'` 时压栈 |
| 4 | `snapshot()` / `restorePlayback()` | `shuffleTrail` 落盘与恢复（过滤非字符串、只留最近 50 条） |

**面板上的上一曲按钮和媒体键 F7 都走 `stepIndex(-1)`，所以自动一起修好，不用另接。**

## 已知边界（都是有意为之）

- **下一曲在随机模式里永远是随机**，不跟随来路前进（罐头要的手感）。所以「上一曲之后再下一曲」不会回到刚才那首，会随机到新的。哪天想要 Spotify 那种前进/后退对称，把栈换成「栈 + 游标」就行，触点不变。
- 没做「3 秒内按上一曲 = 重听本曲」这条（没要求）。
- 来路只在内存 + 快照里；切歌单后旧条目自动失效，不会跳回别的歌单的歌。
