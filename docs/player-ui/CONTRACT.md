# 极简播放器 UI 定稿执行契约

2026-10-08 最新用户指令，覆盖此前 HANDOFF 中保留 PV/场景/编排/收藏/多种视觉模式的要求。

## 先 UI，后业务

主代理负责此目录内的独立、可交互 UI。该目录不属于生产 ui/，使用演示数据，不接真实音频、宿主或持久存储。用户验收后，执行者以此 DOM/CSS/交互为依据接线，不自行换控件或重建一套视觉。之前 Luna 的实现未通过实机及视觉验收，不能作为已完成基线。

## 唯一功能范围

- 播放/暂停、上一首/下一首、进度与时长、音量/静音。
- 播放模式：列表循环、单曲循环、随机播放；一个按钮循环切换，悬浮/焦点提示与无障碍名称说明当前值。
- 歌词显示/隐藏。隐藏时关闭歌词正文与为文字设置的渐变蒙层，完整展示封面图；曲目信息/播放控制用各自局部底色保证可读，不重新盖满整张图。歌词开启时自动跟随仅控制自身；手动浏览暂停跟随，出现“回到当前歌词”。
- 播放列表只有“本地”“在线导入”两类，分别支持文件/文件夹导入和单曲/歌单链接导入。每行封面、歌名、歌手、时长；移除放在曲目更多菜单。不加来源行、自建分组、收藏、推荐、电台、场景或编排。
- 删除 PV、唱盘模式切换、自带主题选择、独立字号按钮、实例编号等入口。生产接线时可整段移除 PV 生成物，不手改其内部后保留半套引擎。主题继续消费宿主 Hana，界面无主题开关；预览台的深浅切换仅用于验证。

## 三种布局

- 矮卡：播放页与队列页互切，底部播放控制始终可见。队列页左上有明确返回按钮。
- 长卡：上方舞台、下方常驻队列、最底部播放控制。歌词与队列分开滚动，滚动不移动顶栏/控制。
- 宽窗：封面场景在左，歌词阅读列在右；队列从右侧作为舞台内部浮层打开，关闭图标与全部按钮使用同一套样式。抽屉只覆盖舞台，不压缩舞台，不遮住底部播放控制。
- 根容器直角，无外描边/外阴影；顶部右侧100×40 CSS px留给宿主；不画第二套原生窗口按钮。所有字>=11px。

## 记忆与音频所有权（接线硬要求）

持久化：曲目稳定ID与本地/在线类别、列表顺序、当前曲目ID、播放进度秒数、音量/静音、播放模式、歌词显示状态、上次是否播放。用公开 App 存储或既有 app-data 后端；不由视图直接写 localStorage，不清空用户已有列表。导入项按稳定标识去重，不仅按 URL 去query后的值去重。

启动：先读状态、恢复列表与当前曲目，音频 metadata 可用后把进度限制到有效时长再恢复；上次暂停则保持暂停，上次播放则尝试继续，受宿主/浏览器限制失败时明确显示需点击播放，不假装已播放。文件丢失/链接过期时保留该曲目并给出可恢复提示，不能悄悄换歌。持久化写入节流并串行，切歌/暂停等边界立即保存，过期异步结果不能覆盖新状态。

独立窗口回到小卡目前会停止音乐，原因未核实。必须在 Hana 实际检查页面销毁/重载、audio实例生命周期和实例锁。播放所有权不能绑在可随时重建的视图上；先确认宿主公开API是否支持持续的音频承载，再确定架构。不用“回挂后seek并重播”冒充连续播放，不承诺纯前端一定能解决宿主销毁页面造成的中断。

## 验收

先验证本 UI：465×930、585×1172、531×451、560×616、1040×740/780；浅深主题、无歌词/无封面/长标题、大字；队列抽屉与翻页；歌词隐藏后背景无遮罩；48首队列可滚底；所有播放控制在容器内且实际可见。

再验证接线：真实导入/删除/连续播放；跨重启记忆恢复；独立窗与小卡双向切换音频不中断；歌词连续换行时队列位置不变；陈旧请求不覆盖新歌。宿主专测另给 HanaAgent Markdown 步骤，未测不得报告通过。

演示封面 demo-cover.png 使用内置 GPT image_gen 生成，仅用于此预览，不作为生产所有曲目的固定背景。提示词：静谧的清晨远山、云海与左下方金色草坡，低饱和电影摄影，右侧较平静，无人物/文字/界面/边框；实际遮罩由 CSS 控制。
