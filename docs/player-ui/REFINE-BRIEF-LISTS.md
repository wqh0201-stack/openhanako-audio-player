## 一、目标形态

播放列表（`#queue`）从「一锅乱炖的单一平铺列表」改成**多个命名列表 + 顶部切换**：

```
┌─────────────────────────────────────────────┐
│  [本地] [1] [2] [3] [4]              ＋     │   ← 顶部切换条
├─────────────────────────────────────────────┤
│  ▢ 歌名 / 歌手                       3:45 ⋯ │
│  ▢ ...                                      │
└─────────────────────────────────────────────┘
```

- **本地**：一页本地列表，数据来自**一个固定文件夹**（用户选一次就记住）。
- **1 / 2 / 3 / 4…**：每次**导入一个歌单**就是一条独立列表，按导入顺序编号；有几个显示几个。
- 顶部按钮切换当前查看的列表；`＋` 仍是导入入口。
- **精简**：砍掉「电台流 / TTS / 自定义分组 / 收藏」这类来源分类，只留「本地」+「导入歌单」。

## 二、数据模型（关键）

给每条曲目加一个 **`list`** 字段：

| 值 | 含义 |
|---|---|
| `"local"` | 属于本地列表（固定文件夹扫描出来的） |
| `"imp:1"` `"imp:2"` … | 属于第 N 个导入歌单 |

- 列表显示名：`local` → 「本地」；`imp:N` → 数字 `N`（原始歌单名另存 `listName`，用作 `title` 提示，不占主标签）。
- **列表本身也要持久化**（顺序、原始名）：建议存 `hana.storage.global` 一个键（如 `player-lists`），
  形如 `[{ id:"local", name:"本地" }, { id:"imp:1", name:"Can_0201喜欢的音乐", source:"netease" }, …]`。
  曲目写在 `playlist.json`（含 `list` 字段）。
- 同一首歌**可以同时存在于多个列表**（它确实在两个歌单里，不算重复）。

## 三、必须处理的坑

1. **后端去重会误并**：`lib/register-routes.js` 的 `trackKey(t)` 现在只用 `id` / `url`。
   同一首歌进了两个列表 → 同一个稳定 id → `POST /widget/api/playlist` 去重时**并成一条**，丢一个列表的归属。
   必须把 `list` 纳入去重键（如 `id:${list}|${id}`）。**这是后端改动，允许动 `lib/register-routes.js`。**
2. **旧数据迁移**（`app-data/hanako-audio-player/playlist.json` 现有 203 条，**没有 `list` 字段**）：
   - `mode === "本地"` → `list:"local"`。
   - 其余（在线）→ **按原 `group` 各自成一个导入列表**（列表名用原 group，如「鸣潮」「电台流」「在线音乐」），
     尽量保住用户已有的组织；group 缺失的归一个「未分类」列表。
   - 迁移后在**每个列表内**按稳定 id 去重；跨列表不去重。
   - **不丢数据**：迁移后每首歌都能在某个列表里找到。
   - 迁移要**幂等**：已经有 `list` 字段的数据再跑一次不改变结构。
3. **本地固定文件夹**：选中的绝对路径存 `hana.storage.global`（如 `player-local-dir`）。
   本地列表 = 扫这个文件夹（后端 `GET /widget/api/scan-folder?path=`）。
   - 没设过文件夹时，本地页给一个明确的「选择文件夹」引导，而不是空白。
   - 文件夹用 `hana.resources.pick({ mode:'directory' })`（注意：卡片里可能没有宿主，要优雅降级 + 提示）。
4. **不要动** `appSurfaceSession` 鉴权那层（app.js 里 `apiFetch`/`withSession`），所有后端调用必须继续带票。

## 五、主题：跟随 macOS 夜间模式

- 用户要求：**读取 macOS 夜间模式自动切换**。
- 做法：`@media (prefers-color-scheme: dark)` 兜底切 `--hk-*` 那一层到夜间一套
  （深板岩 `#34424B` / 面 `#414D56` / 文字 `#E1EAF0`、`#9FB1BC` / 强调藕荷粉 `#C99AAF`）。
- 优先级：**宿主显式注入的值 > prefers-color-scheme 兜底 > 写死默认**。
  ⚠️ 已知风险：宿主主题可能压根没注入卡片 iframe（线上日志没见过 `theme.css` 请求），所以这条兜底很关键。
- 另一个同事（主工作树）也在改主题兜底 —— **你只管 `prefers-color-scheme` 这一层**，别改 `--hk-*` 的定义行结构。
