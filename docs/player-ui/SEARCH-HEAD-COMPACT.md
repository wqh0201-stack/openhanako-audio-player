# 卡片里搜索页头部收矮（SEARCH-HEAD-COMPACT）

2026-10-10。罐头真机反馈：「窄卡里搜索页那三行头部会不会显高」——**会**。
**已部署**，构建号 1003131619 → **1003131620**。改动落在 `ui/index.html` /
`ui/standalone.html` / `ui/style.css`（+ `tools/verify-ui.mjs` 三条断言）。

---

## 1. 账先算清楚

罐头那张卡约 560×500。搜索页头部原来是**四行**：

| 行 | 内容 | 高 |
|---|---|---|
| 1 | 返回 + 输入框 + 搜索 | ~50px |
| 2 | 平台条（网易云/B站/QQ/酷狗） | ~34px |
| 3 | 范围（搜歌曲/搜歌手） | ~36px |
| 4 | 「歌手结果」标签 | ~20px |

连内外边距 **约 137px**。那张卡的舞台只有 ~388px（底下控制条 112）——**三分之一给了头部**，
结果列表只剩两条的可见高度。

## 2. 做法：四行 → 两行

- **行 1** 返回 + 输入框 + 搜索（不动）
- **行 2** 平台条 + 范围并排 —— 两者都是筛选条件，一个选"去哪找"、一个选"找什么"，
  本来就该同行。结构上给它们套了个 `.search-filters` 容器。
- **「歌曲结果 / 歌手结果」那行在卡片里省掉**：范围按钮的选中态 + 底部那句
  「共 N 条 · 来自 X」已经说全了。

实测（`verify-ui` 跑出来的数）：头部 **137 → 94px**，结果列表可见高度 **→ 280px**（561 宽）
/ **262px**（312 宽）。

### 2.1 宽窗也跟着变了一行

`search-filters` 容器让宽窗的「平台 + 范围」并到了输入框那一行（1040 宽下放得下），
头部从两行变一行（**63px**）。这是顺带的，罐头看过认可。
「结果」标签在宽窗**保留**（有地方，多一句上下文没坏处）。

### 2.2 极窄卡：平台条横滑，范围恒可见

312 宽时那一行放不下 4 个平台 + 2 个范围按钮，所以：

```css
.player:not([data-layout="wide"]) .search-servers {
  flex: 1 1 auto; min-width: 0; flex-wrap: nowrap; overflow-x: auto; scrollbar-width: none;
}
```

平台条自己横滑，**范围固定在它右侧、永远完整可见**。优先级是对的：
从歌手名进来时范围已经定好，平台很少改。截图里平台条在 QQ 处截断 —— 就是在提示"后面还有"。

## 3. 踩到的一个坑（值得记）

第一版收完，312 那档头部还是 **132px**（三行）——**返回键被顶到了单独一行**。

原因不在平台/范围，在搜索框：`.search-bar` 是 `flex: 1 1 auto`，而它的 flex-basis 取
"内容尺寸"，里面那个 `<input>` 的**固有宽度**很大（浏览器按 `size` 给），于是
「返回 + 搜索框」这一行的**假设尺寸超了容器**，flex 的换行算法在搜索框之前就断了行。

**修**：非宽窗里把搜索框的 basis 压到 0：

```css
.player:not([data-layout="wide"]) .search-bar { flex: 1 1 0; min-width: 140px; }
```

basis 0 之后它的假设尺寸只剩 `min-width`，不抢行；真宽度靠 `flex-grow` 吃满余量。
**教训**：窄容器里凡是"要跟别的东西并排"的输入框，`flex-basis` 别留 auto ——
`<input>` 的固有宽度会把布局算歪。

## 4. 验收

`node tools/verify-ui.mjs` → **114/114** 断言、12/12 布局、4/4 窄卡、零运行时错误。
新增三条（2e 段，三档尺寸各跑一遍）：

| 断言 | 证什么 |
|---|---|
| `search-head-compact-two-rows` | 561×500：头部 ≤110px、平台与范围 `top` 差 <2px、范围完整可见、「结果」标签被 CSS 隐去、列表 ≥230px、不横溢 |
| `search-head-narrow-two-rows` | 312×494：同上，且平台条确实开始横滑（`scrollWidth > clientWidth`） |
| `search-head-wide-single-row` | 1040×780：头部 ≤72px（一行）、「结果」标签仍显示 |

「结果」标签那条断言的做法：探针里**临时拿掉 `hidden` 再读计算样式** ——
否则 `display:none` 可能来自元素自己的 `hidden`，验不到 CSS 那条规则。
