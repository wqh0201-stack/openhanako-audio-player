# 歌单改名不持久化（已修）

> 2026-10-09 罐头反馈「歌单改名后没法持久化，每次重载都消失」。真机验收通过。
> 部署：构建号 **1003131567**。

## 根因

`boot()` 跑在 `app.js`（`defer`）里，**早于** `sdk.js`（`<script type="module">`）执行 ——
那一刻 `window.hana` 还没有，`hanaStorage()` 返回 `null`，所以 boot 里那三处读存储
**每次都立刻读回 `null`**。而旧代码在列表加载后**无条件** `saveLists()`，就用默认名
「歌单 N」把用户改过的真名覆盖掉了。

**关键分界**：写一直是好的（发生在用户操作时，SDK 早已就绪）。`app-data/storage/global.json`
里确实存到过 `imp:1 = "Can网易"`，只是每次启动又被冲掉 —— 所以症状像「存不住」，实为「读不回」。

## 修法

1. `waitForHana()` 之后再读存储（不再空读）。
2. 两段式：列表先用**派生名**立起来（首屏不等存储读取，宿主桥不应答也不卡），
   读到存储后再套用**真名 / 本地目录 / 分隔比例**，且只在名字真变了才 `renderAll()`。
3. `storeRead(key)` 返回 `{ ok, value }`：**读失败绝不回写默认值**（宁可显示旧名，
   也不能覆盖盘上真名）。
4. 顺手修了一个自己引入的顺序错：`applyTracks()` 必须在 `savePlaylist()` 之前
   （后者读 `state.tracks`，否则回写空列表）。

## 验证

- `verify-ui`：12/12 布局自检 + 4/4 窄卡 + **56/56 断言** + migration / lifecycle 全过、0 运行时报错。
- 真机：改名 → reload → 名字仍在（存储文件实测 `imp:1 = "Can网易"`）。
